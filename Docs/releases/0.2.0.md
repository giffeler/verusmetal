# VerusMetal 0.2.0 — 2026-09-28

This public preview prepares the job-constant VerusHash state once and searches
nonces on the GPU with a shared pristine key and private mutation overlays.
The standalone Apple Silicon executable requires macOS 27 or later.

## Changes

- Per-job key caching and an independently written carry-less multiply improve
  command end-to-end throughput by 2.22–2.23x at equal batch size on Apple M4.
  Paired, interleaved comparisons ran in both argument orders with an
  identical-source control. A separate ten-second CLI benchmark reached about
  3.65 MH/s using the real 1,487-byte layout. These are short synthetic tests;
  no new live-pool or sustained thermal result is claimed.
- The default batch is now 32,768 nonces. Explicit Metal buffers use about
  257 MiB at that setting, plus Metal overhead and threadgroup masks.
  `--batch-nonces 4096` remains available for a smaller allocation.
- The canonical CPU API exposes reusable preparation and nonce completion.
  Layouts with a nonce overlapping a full block fall back to full hashing.
  CPU share verification still uses the full reference hash. There is no CPU
  mining mode; TLS certificate validation and transport policy are unchanged.

## Validation

All 18 unit tests, CLI/local-pool integration, CPU sanitizers and Metal validation
passed. All 148 independent vectors pass on the full and split CPU/GPU paths.
Additional checks cover 8,192 primitive cases, 512 directed mix cases, random
nonces, prefix lengths 1–14, repeated dispatches, partial groups, version-7/8
PBaaS jobs and the full-block fallback. Optimized AIR contains no application
helper calls. The divergence-binning research prototype was slower and is not
included in the executable.

See [the research report](../research/KEY-CACHING.md) for raw evidence, timing
boundaries, resource metrics and reproduction commands.
